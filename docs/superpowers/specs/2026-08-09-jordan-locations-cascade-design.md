# الكاسكيد الرسمي للمناطق الأردنية (محافظة ← لواء ← قضاء ← منطقة)

التاريخ: 2026-08-09
الحالة: معتمد من المستخدم

## مشكلة

1. **بيانات المناطق حالياً غير رسمية**: `js/jordan-locations.js` يحتوي كائن `window.JORDAN` ببيانات قديمة/منقوصة (12 مدينة، أحياء مخترعة مثل "مثلث الصويفية") لا تطابق التقسيمات الإدارية الرسمية.
2. **عمق متغير غير مدعوم**: البيانات الرسمية الجديدة بعمق 3-4 مستويات — بعض الألوية تحتها أقضية (المفرق، الزرقاء) وبعضها مناطق مباشرة — بينما الكاسكيد الحالي `cascadeCity` ثابت بثلاثة مستويات (مدينة → حي → منطقة).
3. **مستوى القضاء غير محفوظ**: الخادم يخزّن `city/district/area` ولا يعرف `subdistrict`.

## نظرة عامة

- استبدال بيانات `window.JORDAN` ببيانات التقسيمات الرسمية (`JORDAN_LOCATIONS`) كما أرسلها المستخدم، مع طبقة وصول نقية.
- تعميم الكاسكيد إلى `cascadeSelects` يدعم 3-4 مستويات ديناميكياً: حقل القضاء يظهر فقط عندما يكون للواء المختار أقضية.
- حفظ `subdistrict` في ملف التوصيل `data/delivery-info.json` وسلسلة عنوان الطلب، دون تغيير قاعدة البيانات.
- إعادة تسمية التسميات: المدينة → المحافظة، الحي → اللواء، + حقل القضاء.

## المتطلبات

1. القوائم المتسلسلة (محافظة → لواء → [قضاء] → منطقة) مبنية على بيانات التقسيمات الرسمية.
2. عند اختيار لواء بأقضية (مثل لواء قصبة المفرق): يظهر حقل القضاء ويصبح إلزامياً قبل اختيار المنطقة.
3. عند اختيار لواء بلا أقضية (مثل لواء قصبة إربد): لا يظهر حقل القضاء، وتُعرض مناطق اللواء مباشرة.
4. تغيير أي مستوى أعلى يصفّر كل المستويات الأدنى.
5. `subdistrict` يُحفظ في `data/delivery-info.json` ويُدمج في سلسلة عنوان الطلب.
6. الاستعادة التلقائية لبيانات التوصيل (من حساب Google أو آخر طلب) تملأ كل المستويات بما فيها القضاء.

## تفاصيل التنفيذ

### 1) البيانات — `js/jordan-locations.js` (استبدال كامل)

- `window.JORDAN_LOCATIONS` = مصفوفة المستخدم كما هي حرفياً: `{ city, districts: [{ district, subdistricts?: [{ subdistrict, areas }], areas? }] }`.
- دوال وصول نقية فوق البيانات (تُعرَّض على الكائن نفسه لتكون قابلة للاختبار في Node عبر `module.exports` عند غياب `window`):
  - `cities()` → أسماء المحافظات (12).
  - `districts(city)` → أسماء الألوية.
  - `subdistricts(city, district)` → مصفوفة أسماء الأقضية، أو `null` إذا كان اللواء بلا أقضية.
  - `areas(city, district, subdistrict?)` → مناطق القضاء إن وُجد subdistrict، وإلا مناطق اللواء المباشرة، وإلا `[]`.
- ملاحظة: تكرار بعض أسماء المناطق بين أقضية مختلفة (مثل "الكوم الأحمر") حقيقي في البيانات الرسمية ويُبقى كما هو.
- كل دوال الوصول تعيد `[]` عند إدخال غير موجود (لا ترمي أخطاء).

### 2) الكاسكيد — `js/my-orders.js`

- إزالة `cascadeCity` واستبدالها بدالة عامة:
  - `cascadeSelects(selCity, selDistrict, selSub, selArea, cityId, districtId, subId, subFieldId)`:
    - المحافظة: خيارات = `cities()`؛ عند الاختيار → تصفير اللواء/القضاء/المنطقة وإخفاء حقل القضاء.
    - اللواء: خيارات = `districts(city)`؛ عند الاختيار → تصفير القضاء/المنطقة، ثم:
      - إن كانت `subdistricts(city, district)` غير فارغة → إظهار حقل القضاء (`subFieldId` style.display = '' ) وتمكين خياراته؛
      - وإلا → إخفاء حقل القضاء وتصفيره، وخيارات المنطقة = `areas(city, district)`.
    - القضاء: خيارات = `subdistricts(...)`؛ عند الاختيار → تصفير المنطقة، خياراتها = `areas(city, district, subdistrict)`.
    - المنطقة: خيارات كما حددها المستوى الأعلى.
- استدعاءان: `cascadeSelects(..., 'mo-*')` و `cascadeSelects(..., 'mo-del-*')`.
- `applyDelivery(d)` يضيف `$('wrap-mo-subdistrict')._setVal(d.subdistrict || '')` + إظهار/إخفاء حقل القضاء حسب القيمة المحفوظة (إن وُجدت subdistrict محفوظة يظهر الحقل ويملأها).
- `loadDelivery` (ملء من آخر طلب عند إدخال رقم الهاتف) يمرر `subdistrict` إن وُجد.
- إرسال الطلب: جمع `subdistrict` في سلسلة العنوان `[city, district, subdistrict, area, street, landmark]` وإرسالها في body مع بقية الحقول.
- حفظ بيانات التوصيل: تمرير `subdistrict` في body.
- `makeSelect` يبقى كما هو دون تغيير.

### 3) الواجهة — `my-orders.html`

- في نموذج الدفع (بعد `wrap-mo-district`): إضافة
  `<div class="mo-field" id="field-mo-subdistrict" style="display:none"><label>القضاء</label><input type="hidden" id="mo-subdistrict"><div class="mo-select" id="wrap-mo-subdistrict" data-for="mo-subdistrict" data-placeholder="اختر القضاء"></div></div>`.
- في محرر التوصيل (بعد `wrap-mo-del-district`): إضافة المعرّفات المكافئة `field-mo-del-subdistrict` / `mo-del-subdistrict` / `wrap-mo-del-subdistrict`.
- إعادة تسمية: "المدينة *" → "المحافظة *"، "الحي *" → "اللواء *" (ومثيلاهما في محرر التوصيل).

### 4) الخادم — `server.js`

- `sanitizeDelivery` (سطر 284-295): إضافة `subdistrict: s(body.subdistrict, 40)`.
- لا تغيير على قاعدة البيانات أو مسارات الطلبات (body يمرر `subdistrict` مع الحقول، والـ sanitize يقبله).

### 5) الاختبار — `tests/locations.test.js` (جديد)

- وحدة Vitest (بيئة node) على طبقة الوصول: استيراد `js/jordan-locations.js` عبر `module.exports`:
  - `cities()` تعيد 12 محافظة وتشمل "المفرق".
  - `districts('المفرق')` تشمل "لواء قصبة المفرق".
  - `subdistricts('المفرق', 'لواء قصبة المفرق')` تعيد 4 أقضية.
  - `subdistricts('إربد', 'لواء قصبة إربد')` تساوي `null`.
  - `areas('إربد', 'لواء قصبة إربد')` تشمل "إربد" (مسار مباشر).
  - `areas('المفرق', 'لواء قصبة المفرق', 'قضاء بلعما')` تشمل "بلعما" (مسار قضاء).
  - مدخلات غير موجودة تعيد `[]` بلا خطأ.

## الحواف

- لواء بلا `subdistricts` ولا `areas` في البيانات → المنطقة فارغة (بيانات ناقصة لا تكسر الصفحة).
- حفظ بيانات توصيل قديمة بلا `subdistrict` (قبل هذا التحديث) → `_setVal('')` بلا مشكلة ويبقى الحقل مخفياً.
- اختيار محافظة/لواء جديد بعد تعبئة كاملة → كل المستويات الأدنى تتصفّر وتُخفى القائمة الإضافية إن لم تعد مطلوبة.
- أسماء متطابقة بين لواء وآخر في نفس المحافظة (مثل "الكوم الأحمر" في المفرق) مقبولة لأن الاختيار يُبنى من قوائم ثابتة لا بحث نصي.
- حدود الأحرف: `subdistrict` مقصوصة لـ 40 حرفاً في الخادم (مثل بقية حقول الموقع).

## استراتيجية الاختبار

- `npm test` (يشمل `tests/locations.test.js` الجديد).
- `npm run lint` (يشمل `js/` و `server.js`).
- فتح `my-orders.html` محلياً: التحقق من السيناريوهات الثلاثة (لواء بأقضية، لواء بلا أقضية، تغيير المحافظة يصفّر كل شيء) لكل من نموذج الدفع ومحرر التوصيل، ومن حفظ/استعادة `subdistrict` بعد إعادة تحميل الصفحة (بيانات التوصيل المسجلة).
