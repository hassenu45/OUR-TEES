# إعادة تصميم صفحة "طلباتي" (My Orders) — تصميم

التاريخ: 2026-08-08
الفرع: my-orders-feature
النطاق: my-orders.html فقط (النهج 1 — إعادة تصميم في مكانها)

## السياق

صفحة `my-orders.html` (مع `js/my-orders.js`) هي صفحة العميل بتبويبين: **إتمام الطلب** (سلة + نموذج توصيل + طريقة دفع) و**طلباتي** (بحث برقم الهاتف + قائمة الطلبات + إلغاء). الوظائف مكتملة وتعمل، لكن الشكل الحالي بسيط وظيفي فقط.

**هوية الموقع (OUR TEES)**: أسود `#0D0D0D`، سطح `#161616`، ذهبي `#F5C842`، حدود `rgba(255,255,255,.08)`، خطوط Cormorant (عناوين) + Montserrat (واجهة). التوكنز تُعرّف محلياً بأسماء `--tees-*` (كما في store.html).

**خطأ مُصلَح**: وسم `<div>` غير مغلق في حقل الملاحظات (كان يبتلع لوحي الطلبات والطبقة داخل لوحة الدفع). البناء الجديد يحافظ على التوازن (26/26).

## الهدف

رفع الصفحة لمستوى "بوتيك فاخر" بمعايير وكالات: طباعة تحريرية، مسافات فاخرة، زجاجية، حركات دقيقة من مهارات الأنيميشن (animate + emil-design-eng + apple-design للفيزياء والسلاسة) — بدون مكتبات خارجية، بدون كسر وظائف، وبدون تغيير سلوك الخادم.

## القيود الصارمة (غير قابلة للتفاوض)

1. كل معرّفات العناصر تبقى كما هي: `mo-name, mo-phone, mo-city, mo-area, mo-street, mo-landmark, mo-notes, pay-cod, pay-card, mo-error, mo-submit, mo-cart-items, mo-cart-total, tab-checkout, tab-orders, panel-checkout, panel-orders, mo-phone-panel, mo-lookup-phone, mo-orders-panel, mo-customer-name, mo-orders-list, mo-overlay, mo-overlay-text`.
2. كل دوال `my-orders.js` تبقى بدون تغيير منطقي: `switchTab, pickPayment, submitOrderFlow, loadMyOrders, lookupOrders, cancelOrder, renderCart, showToast, showError, showOverlay, hideOverlay, fmt, initMyOrders`.
3. التوكنز بأسماء `--tees-*` (نسخ قيم المتجر) داخل `<style>` الصفحة.
4. RTL أولاً — كل الاتجاهات والمسافات عربية.
5. لا تغيير في: `js/api.js`، `js/db-local.js`، `server.js`، قاعدة البيانات. `js/my-orders.js` لا يتغير إلا إذا اكتُشف فراغ في سلسلة الحفظ التلقائي (تغيير بسيط جداً موثّق في التقرير) — وإلا لا يلمس.
6. ملف واحد يُعدَّل: `my-orders.html` (إعادة هيكلة + تنسيقات + حركات).

## التصميم البصري

### الهيرو
- شريط علوي (sticky) بنمط المتجر: شعار OUR TEES بخط Cormorant + "MY ORDERS" صغيرة باهتة، زر "→ العودة للمتجر" بمحيط ذهبي هادئ.
- عنوان الصفحة: "طلباتي" Cormorant 44px بتدرج أبيض→ذهبي خفيف، تحته خط ذهبي رفيع (gradient line) + "MY ORDERS" بترجم باهت.

### التبويبات
- حبة واحدة (pill container) بخلفية سطح، التبويب النشط: تعبئة ذهبية شفافة + حد ذهبي + نص ذهبي، مع مؤشر انزلاقي ناعم.

### البنية
- عمود واحد مركزي max-width 720px.
- بطاقات: `background: linear-gradient(rgba(255,255,255,.03), rgba(255,255,255,.01))` + حد 1px `rgba(245,200,66,.15)` + زوايا 18px + توهج علوي خفيف.
- هامش داخلي 24px، فجوات 16px.

### نموذج الطلب
- حقول: خلفية `rgba(255,255,255,.04)`، حدود `rgba(255,255,255,.1)`، زوايا 10px، تركيز: حد ذهبي متوهج (box-shadow gold 0 0 0 3px rgba(245,200,66,.12)).
- طريقة الدفع: بطاقتان متجاورتان، المحددة بحد ذهبي + علامة ✓ ذهبية متحركة.
- زر التأكيد: تدرج ذهبي (dark→gold)، لمعان يمرّ عند التمرير (shine sweep)، حالة معطّل باهتة.

### ملخص الطلب
- صفوف منتجات: صورة مستديرة 12px، اسم + meta صغير، سعر ذهبي.
- فاصل منقّط بين الصفوف والمجموع؛ المجموع Cormorant 22px ذهبي.

### قائمة الطلبات
- بطاقة طلب: اسم المنتج بخط عريض، شارات حالة ملوّنة هادئة (جديد أصفر، مكتمل أخضر، ملغي أحمر + 💳/💵)، meta (المقاس/النوع/السعر/التاريخ) بخط 11px باهت، زر إلغاء بمحيط أحمر ناعم.

### الحالات الفارغة
- أيقونة SVG ذهبية (خطية، 48px) + رسالة باهتة + زر "تصفح المتجر" ذهبي (رابط store.html).

### الطبقة (overlay)
- خلفية معتمة + blur، بطاقة زجاجية، حلقة دوّارة ذهبية، نص "جاري معالجة الدفع...". تظهر بشكل صحيح (إصلاح التداخل محفوظ).

## الحركات (من مهارات الأنيميشن)

1. **ظهور متدرج**: عناصر الهيرو/البطاقات fade-up بترتيب متدرج (stagger 60-90ms)، مدة 500-650ms، `cubic-bezier(.22,1,.36,1)`، احترام `prefers-reduced-motion`.
2. **انتقال التبويبات**: panel ينسحب/يظهر بـ fade + translateY(8px) قصير، 300ms.
3. **أنيميشن النجاح**: بعد إرسال الطلب — علامة ✓ في دائرة تتنفّس (scale 1→1.1→1) ثم انتقال تلقائي لتبويب الطلبات.
4. **لمعة الزر**: shine sweep عند hover (500ms).
5. **نبض خفيف** على زر التأكيد عند تفعيل السلة (اختياري، مرتين فقط).
6. **اهتزاز ناعم** لحقل غير صالح عند رسالة الخطأ (shake 300ms، إزاحة 4px).

## إكمال ميزة الحفظ التلقائي (تحقق + سد فراغات)

السلسلة المطلوبة: طلب جديد → يُحفظ العميل (الاسم/الهاتف/العنوان) → بحث لاحقاً بنفس الهاتف → النموذج يتعبأ تلقائياً.

التحقق في **الوضعين** (سيرفر: `API.getCustomerByPhone`/`submitOrder` عبر `POST /api/orders` مع upsert العميل؛ محلي: `DB.createOrder` + البحث المحلي):
- عند الطلب بالهاتف X والعنوان A: هل يُحفظ العميل X بالعنوان A؟
- عند طلب لاحق بنفس X وعنوان مختلف B: هل يتحدّث العنوان إلى B؟
- عند البحث عن X: هل يتعبأ النموذج بالعنوان المحفوظ؟
- أي نقص في الوضع المحلي أو السيرفر يُصلَح في `js/my-orders.js` فقط (تغيير بسيط موثّق) — لأن القيد 5 يمنع المساس بالملفات الأخرى.

## الحالات الطرفية

- سلة فارغة: رسالة + زر عودة، زر معطّل.
- رقم غير موجود: حالة فارغة + اقتراح متجر.
- رقم غير صالح: رسالة + اهتزاز.
- فشل الإرسال: رسالة + إعادة تمكين الزر.
- إلغاء: confirm + توست (جديد/فشل) بأسلوب جديد (زجاجي، 2.6s).
- RTL كامل، توست سفلي في المنتصف.

## التحقق بعد التنفيذ

1. فتح `http://localhost:3000/my-orders.html` (السيرفر يعمل) — الكونسول صفر أخطاء.
2. تبويب طلباتي: بحث `0791234567` → قائمة الطلبات (موجودة في dev.db).
3. تبويب إتمام الطلب: تحقق من التعبئة التلقائية عند البحث أولاً.
4. div balance 26/26 + لا بقايا `checkout-form`.
5. reduced-motion: لا حركات عند تفعيله (فحص بصري/كودي).
6. الإصلاح السابق (وسم ناقص) محفوظ — التبويبات والطبقة تعمل.
