# التحديث الصامت للمتجر + إصلاح فرش التطبيق + وضع مفتح

التاريخ: 2026-08-09
الحالة: معتمد من المستخدم

## مشكلة

1. **موقع العميل لا يحدّث نفسه**: الزبون يفتح المتجر ولا يرى المنتجات الجديدة إلا بعد تحديث الصفحة يدوياً. المستخدم يريد أن يرى العميل المنتجات الجديدة تلقائياً وبصمت (بدون ومضة/فقدان مكان).
2. **محدّث التطبيق (desktop) يفرش النافذة قسرياً**: عند وجود نسخة جديدة بعد إقلاع التطبيق، `desktop/main.js` يعمل `win.reload()` تلقائياً (~4-8 ثوانٍ بعد الفتح) فيضيع على المستخدم أي كتابة/نموذج مفتوح.
3. **لا يوجد وضع فاتح**: اللوحة داكنة دائماً؛ المستخدم يريد سويتش داكن/فاتح أعلى الشريط الجانبي.

## نظرة عامة

- إضافة **مزامنة صامتة** لصفحة المتجر: فحص دوري كل 20 ثانية + فحص فوري عند إعادة الظهور للتبويب، مع إعادة رسم الشبكة بدون فقدان سكرول/سلة/بحث/فلاتر، وتنبيه لطيف عند ظهور منتجات جديدة فقط.
- تعديل تدفق تحديث التطبيق: التنزيل بالخلفية + إشعار عبر IPC بدل إعادة التحميل القسرية؛ الزر يتحول إلى "أعد التحميل" عند الطلب.
- إضافة سويتش داكن/فاتح (شمس/قمر) أعلى الشريط الجانبي، الافتراضي داكن، محفوظ في localStorage، مع تعديل ألوان الرسم البياني حسب الوضع.

## المتطلبات

1. المتجر يتحدّث تلقائياً كل 20 ثانية بلا إعادة تحميل للصفحة.
2. التحديث يحافظ على: موضع السكرول، السلة (localStorage `azma_cart`)، البحث، الترتيب، الفلاتر، المودال المفتوح، المحادثة.
3. عند زيادة عدد المنتجات فقط: تنبيه صغير "منتجات جديدة".
4. عند إعادة ظهور التبويب: مزامنة فورية؛ والفحص الدوري يتوقف والتبويب مخفي.
5. التطبيق لا يفرش النافذة قسرياً بعد تنزيل تحديث؛ يُشعر المستخدم ويترك له زر "أعد التحميل".
6. سويتش شمس/قمر أعلى الشريط الجانبي (جنب شعار AZMA)، افتراضي داكن، محفوظ، يغطي كل اللوحة بما فيها الرسم البياني.

## تفاصيل التنفيذ

### 1) مزامنة المتجر (`js/store.js` — الجذر)

- متغيرات: `liveSyncTimer`، `lastProductsSignature` (توقيع سلسلة: `id|soldOut|price|name|updatedAt` لكل منتج).
- `syncProductsSilently()`: إذا `document.visibilityState === 'hidden'` ارجع. جلب `API.getProducts()`؛ إذا التوقيع مطابق ارجع بدون رسم. وإلا: احفظ التوقيع، حدّث `products`، وأعد الرسم عبر `filterStoreProducts()`/`sortStoreProducts()` (تُعيد تطبيق البحث والترتيب والفلاتر تلقائياً) بدل `renderProducts()` المباشر. عند زيادة العدد: عرض تنبيه صغير لطيف.
- الإقلاع: بعد `initStore()` فعّل `lastProductsSignature` وابدأ `setInterval(syncProductsSilently, 20000)`.
- `visibilitychange`: عند `visible` → مزامنة فورية.
- لا يلمس: المودال المفتوح (يقرأ من `selectedProduct` — مرجع قائم)، السلة (لقطات بيانات ذاتية).

### 2) إصلاح فرش التطبيق

- `desktop/main.js` (جزء المحدّث ~سطر 320-329): لا `win.reload()` بعد التحديث أثناء boot؛ يرسل IPC `updater:applied` مع `data = { background: true }` بعد التنزيل الصامت.
- `desktop/preload.js`: يمرر `data` لمعالج `onUpdateApplied` (موجود أصلاً).
- `js/admin.js` (الجذر) `onUpdateApplied(data)`:
  - `background: true` (من boot): لا إعادة تحميل؛ toast "تم تنزيل تحديث جديد — اضغط زر التحديث للتطبيق" + زر المحدّث يتحول إلى "أعد التحميل" (يستدعي reload).
  - بدون background (فحص يدوي): السلوك الحالي (إعادة تحميل بعد مهلة قصيرة).
- **ملاحظة نشر**: تغيير main.js لا يصل عبر المحدّث (يحدّث ملفات الويب فقط)؛ يتطلب إعادة بناء نسخة التطبيق `npm run build --prefix desktop` وتثبيتها.

### 3) سويتش داكن/فاتح

- `admin.html` (الجذر): markup السويتش (الكود المعطى من المستخدم) داخل `div.theme-switch` أعلى الشريط الجانبي (صف الشعار). CSS السويتش معزول تحت `.theme-switch` (لأن `.switch`/`.slider` موجودة أصلاً لأزرار الدفع).
- `js/admin.js`: قراءة `localStorage.azma_app_theme` (افتراضي `'dark'` أو غائب)، تطبيق/إزالة `body.light`، حفظ عند التبديل، إعادة رسم الرسم البياني بألوان تبع الوضع.
- CSS `body.light` overrides في نهاية كتلة الـ style في admin.html تغطي: خلفية/نصوص/بطاقات/أزرار/جداول/نماذج/معدلات/صندوق إضافة المنتج + ألوان الرسم البياني.

### 4) النشر

- رفع `VERSION` (الجذر) → `1.0.2`.
- `npm run build:web --prefix desktop` (ينسخ الجذر → `desktop/web`).
- فحوصات: `node --check` لكل ملفات JS معدّلة + `npm test` (إن وجد) + فحص بناء صفحة المتجر.
- نشر المستخدم: `npm run deploy` (Railway) ثم إعادة بناء نسخة التطبيق وتثبيتها (اختياري، لتفعيل إصلاح main.js).

## الحواف

- فشل الجلب أثناء المزامنة: تجاهل صامت والاحتفاظ بالبيانات القديمة والمحاولة لاحقاً.
- `soldOut` تغيّر (منتج انتهى): يحدث بدون تنبيه (التنبيه فقط عند زيادة العدد).
- منتج محذوف: يختفي من الشبكة بصمت؛ إن كان مفتوحاً بمودال يبقى المودال يعمل (نادر).
- رحلات كثيرة من زبائن متعددين: 20 ثانية فحص خفيف `/api/products` (مقبول من الاختبار السابق).
- قبل إعادة رسم الشبكة يجب إعادة تطبيق البحث/الترتيب الحاليين (عبر الدوال الموجودة) وإلا ضاعت حالة الفلترة.
- تحديث الإصدار سيُفعّل المحدّث عند الإقلاع القادم — مع الإصلاح الجديد لا فرش قسري، مجرد إشعار.

## استراتيجية الاختبار

- `node --check` لكل JS معدّل.
- فتح store.html محلياً مع فحص console/شبكة: إضافة منتج من admin ثم ملاحظة ظهوره خلال ≤20 ثانية بدون ريفريش، مع بقاء سكرول/بحث/سلة.
- فحص التطبيق: `npm start --prefix desktop` بعد النشر — التأكد من عدم حدوث reload قسري، وزر "أعد التحميل".
- فحص السويتش: تبديل داكن/فاتح + حفظ الاختيار بعد إعادة الفتح + ألوان الرسم البياني.
