# تصميم: قائمة العناوين المحفوظة بدل التعبئة التلقائية (My Orders)

> **التاريخ:** 2026-08-09
> **الحالة:** معتمدة من العميل (2026-08-09)
> **الغلاف:** تعديل صفحة `my-orders.html` + `js/my-orders.js` + `server.js` — لا يمس تبويب "طلباتي" (يبقى يعرض منتجات السلة) ولا خيارات الدفع ولا تبويبات الصفحة الأخرى.

## 1. الهدف

تغيير سلوك بيانات التوصيل في صفحة إتمام الطلب:

- **قبل:** عند دخول عميل مسجل، تُعبَّأ بيانات التوصيل المحفوظة تلقائياً في حقول الفورم (قائمة ثابتة لا يمكن تعديلها من الصفحة).
- **بعد:** يفتح الفورم فارغاً دائماً. العناوين المحفوظة تظهر كقائمة فوق الفورم يختار منها العميل (فيمتلأ الفورم وقابل للتعديل)، أو يكتب عنواناً جديداً. العنوان المستخدم يُحفظ تلقائياً عند إرسال الطلب. العميل يقدر يضيف أكثر من عنوان ويحذف ما يشاء.

## 2. المتطلبات الوظيفية

### 2.1 الواجهة (my-orders.html + js/my-orders.js)

| # | المتطلب |
|---|---------|
| F1 | الفورم يفتح فارغاً دائماً عند فتح الصفحة — لا تعبئة تلقائية من العنوان المحفوظ |

| F3 | كل عنوان في القائمة يُعرض كبطاقة صغيرة: الاسم، الهاتف، المدينة — الحي — المنطقة + زر حذف × |
| F4 | الضغط على عنوان محفوظ يملأ حقول الفورم منه (ويظل قابلاً للتعديل) |

| F7 | الحفظ تلقائي عند إرسال الطلب الناجح: العنوان المستخدم يُرسل للسيرفر ليُحفظ (بلا تكرار لنفس العنوان) |
| F8 | حذف عنوان محفوظ يزيله نهائياً من السيرفر |
| F9 | حذف نهائي: منيو "📍 بيانات التوصيل" (menu-delivery) + المحرر القديم (mo-delivery-overlay + openDeliveryEditor/closeDeliveryEditor/saveDeliveryEditor) |
| F10 | التحقق قبل الإرسال (الاسم، الهاتف، المدينة) كما هو دون تغيير |
| F11 | خيارا الدفع (إلكتروني/عند الاستلام) كما هما دون تغيير |

### 2.2 السيرفر (server.js + address-book.cjs)

| # | المتطلب |
|---|---------|
| S1 | التخزين يتغير من عنوان واحد لكل بريد إلى **قائمة عناوين**: `data/delivery-info.json` → `{ "<email>": [ {id, name, phone, city, district, area, street, landmark, createdAt, updatedAt}, ... ] }` |
| S2 | توافق رجعي: أي سجل قديم بصيغة كائن واحد `{name, phone, ...}` يُحوَّل تلقائياً إلى قائمة بعنصر واحد عند القراءة (ويُكتب على القرص بالصيغة الجديدة) |
| S3 | منطق القائمة النقي يُستخرج إلى `address-book.cjs`: `normalizeAddress` (تطبيع/قص الحقول)، `sameAddress(a, b)` (مطابقة دقيقة لكل الحقول)، `upsertAddress(list, address)` (إضافة أو تحديث بدون تكرار)، `removeAddress(list, id)`، `MAX_ADDRESSES = 10` (سقف: ما بعد السقف يُرفض الإضافة برسالة) |
| S4 | `GET /api/me/addresses` (محمي بمصادقة) → `{ addresses: [...] }` |
| S5 | `POST /api/me/addresses` (محمي + rateLimit) body = حقلات العنوان → `{ success, addresses }` (يقبل التحديث إذا تطابق العنوان حرفياً — بدون إنشاء نسخة مكررة) |
| S6 | `DELETE /api/me/addresses/:id` (محمي + rateLimit) → `{ success, addresses }` أو 404 |
| S7 | النقاط القديمة `GET /api/me/delivery` و `PUT /api/me/delivery` تُزال نهائياً |
| S8 | توليد المعرّف: `crypto.randomUUID()` |
| S9 | التحقق من الصحة عند الحفظ: `phone` صالح بنفس نمط التحقق الموجود (`/^\+?[0-9\s-]{8,15}$/`)، `name` ≥ 2 حرف، `city` مطلوب — وإلا 400 برسالة عربية |
| S10 | الحفظ على القرص بنفس نمط atomic write الموجود (tmp + rename) |

### 2.3 الحالة الخاصة (حدود/حواف)

- **مسجل + بلا عناوين:** القائمة مخفية والفورم فارغ — بعد أول إرسال يظهر العنوان في القائمة.
- **مسجل يعدّل عنواناً محفوظاً ثم يرسل:** يتغير العنوان فيبقى الأصلي بالقائمة ويُضاف النسخة المعدلة كعنوان جديد (ما لم تكن مطابقة تماماً لعنوان آخر موجود).
- **إرسال نفس العنوان مرتين:** لا يتكرر في القائمة (مطابقة دقيقة عبر `sameAddress`).
- **فشل جلب القائمة من السيرفر (شبكة/خطأ):** تُعرض القائمة فارغة بهدوء (صامت) — الفورم يبقى يعمل كالمعتاد.
- **فشل حفظ العنوان عند الإرسال:** لا يمنع نجاح الطلب — يُسجَّل خطأ في الكونسول فقط.
- **حذف عنوان غير موجود:** 404 برسالة عربية.
- **أكثر من 10 عناوين:** الإضافة تُرفض بـ 400 برسالة "بلغت الحد الأقصى للعناوين المحفوظة".
- **غير مسجل يحاول الوصول لنقاط العناوين:** 401 (المصادقة الموجودة).

### 3.1 الملفات

| الملف | التغيير |
|---|---|
| `address-book.cjs` (جديد) | قواعد نقية: تطبيع، مطابقة، إضافة/تحديث، حذف، سقف |

| `js/my-orders.js` | إلغاء التعبئة التلقائية، عرض/اختيار/حذف العناوين، الحفظ التلقائي عند الإرسال، حذف دوال المحرر القديم |

### 3.2 تدفق البيانات

```
فتح الصفحة (مسجل)
  → GET /api/me/addresses → renderAddressList() فوق الفورم
  → الفورم فارغ

اختيار عنوان محفوظ
  → fillForm(address) — الفورم قابل للتعديل بعدها

إرسال الطلب (نجاح)
  → POST /api/me/addresses (أيضاً بلا انتظار/بلا حجب)
  → تحديث القائمة المعروضة

حذف عنوان
  → DELETE /api/me/addresses/:id
  → تحديث القائمة المعروضة
```

## 4. معايير القبول (Verification)

- `npm run lint` بلا أخطاء جديدة.
- `npm run typecheck` بلا أخطاء جديدة.
- `npx vitest run` — كل الاختبارات تمر بما فيها `tests/address-book.test.js`.
- فحص يدوي:
  1. غير مسجل → لا قائمة عناوين → تعبئة الفورم → إرسال → نجاح.
  2. مسجل (AZMA_DEV_LOGIN=1) بلا عناوين → فورم فارغ → تعبئة → إرسال → العنوان يظهر بالقائمة.
  3. إعادة فتح الصفحة → فورم فارغ + القائمة موجودة → اختيار عنوان → يتملأ الفورم.
  4. تعديل عنوان ثم إرسال → يظهر العنوان الجديد بالقائمة دون تكرار.
  5. حذف عنوان → يختفي نهائياً.
  6. العنوان القديم المحفوظ بالصيغة السابقة (كائن واحد) → يظهر كعنصر واحد في القائمة بعد أول قراءة.

## 5. خارج النطاق (YAGNI)

- لا بوابة دفع حقيقية — الدفع الإلكتروني محاكاة كما هو.
- لا تعديل عنوان محفوظ في مكانه (اختر + عدّل + أرسل = عنوان جديد).
- لا عناوين لغير المسجلين.
- لا تغيير في تبويب "طلباتي" ولا إلغاء الطلبات (موجود فقط في الفورم/الخطط القديمة).
- لا أيام/أوقات توصيل.
