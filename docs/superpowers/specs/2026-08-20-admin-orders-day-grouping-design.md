# تصميم: تجميع الطلبات بالأيام + PDF لكل يوم + فلتر تاريخ (لوحة تحكم AZMA)

**التاريخ:** 2026-08-20
**النطاق:** `admin.html` + `js/admin.js` + ملف جديد `js/order-days.js` + `tests/order-days.test.js`
**بدون تغيير:** `server.js`، `db.cjs`، قاعدة البيانات، أي ملف آخر.

## 1. المطلوب (بعد جلسة أسئلة مع صاحب المتجر)

في صفحة "الطلبات" بلوحة تحكم AZMA (`admin.html` → `panel-orders`):

1. **الطلبات مجمعة بالأيام** — العرض الأساسي: كل يوم قسم فيه طلباته، والأيام مرتبة تنازلياً (الأحدث أولاً)، وداخل كل يوم الطلبات مرتبة **بالتوقيت** (الأحدث أولاً).
2. **فلتر تاريخ** — `<input type="date">` + زر "عرض الكل": اختيار يوم يعرض طلبات هذا اليوم فقط.
3. **زر PDF لكل يوم** — نفس كشف التوصيل الحالي بالضبط (تجميع مناطق + QR اتصال/واتساب + ترتيب أبجدي + pagination) لكن لطلبات ذلك اليوم فقط، واسم الملف `AZMA-Orders-<YYYY-MM-DD>.pdf` وعنوانه بتاريخ اليوم.
4. **إبقاء فلتر الحالة** (جديد/مكتمل/ملغي) — يعمل مع التجميع باليوم.
5. **إزالة:** خيار "تجميع حسب المنطقة" وزر تصدير CSV.
6. **لا تعديل على تواريخ الطلبات** — الفلتر للعرض فقط، بدون أي تغيير في قاعدة البيانات.
7. **الموشن** — أقسام الأيام تُبنى كبطاقات `.card` داخل `#admin-orders-list` فتشملها أنيميشنات `admin-animations.js` الموجودة تلقائياً (دخول البانل + stagger الصفوف) بدون تعديل على طبقة الموشن.

## 2. ملف `js/order-days.js` (جديد)

نمط الملف المزدوج (متصفح + Node للاختبار) مثل `js/pdf-manifest.js`:

- `dayKey(date)` → `"YYYY-MM-DD"` بالتوقيت المحلي؛ تُرجع `null` لتاريخ غير صالح.
- `groupOrdersByDay(orders)` → مصفوفة أقسام: `[{ key, date, orders }]` مرتبة تنازلياً بالمفتاح، وداخل كل يوم `orders` مرتبة تنازلياً بـ `createdAt` (الأحدث أولاً)، مع `null-key` (بدون تاريخ) في النهاية إن وُجد.
- تعريض عام `window.OrderDays` في المتصفح، و`module.exports` في Node.

## 3. `js/admin.js`

- **`renderOrdersList()`** — تقرأ فلتر الحالة + فلتر التاريخ (`#orders-date-filter`) وتستدعي `renderOrdersGroupedByDay(container, filtered)`.
- **`renderOrdersGroupedByDay(container, orders)`** — تبني لكل يوم بطاقة `.card`:
  - شريط اليوم: 📅 التاريخ بالعربي (مثال "الخميس 20 أغسطس 2026") + عدد الطلبات + إجمالي المبلغ + زر `🧾 PDF كشف اليوم` يستدعي `exportDayPDF(key, dayOrders, label)`.
  - جدول بنفس أعمدة وأزرار الجدول الحالي (تسليم/إلغاء/رد ذكي/حذف) + نافذات QR بنفس النمط.
  - قسم "بدون تاريخ" في النهاية (بدون زر PDF إن لم يوجد تاريخ صالح — يظهر فقط إن وُجدت طلبات بدون تاريخ).
  - حالات فارغة: لا طلبات → "لا توجد طلبات." / تاريخ مختار بلا طلبات → "لا توجد طلبات في هذا اليوم.".
- **`exportOrdersPDF()` → `exportDayPDF(dayKey, orders, dayLabel)`** — نفس الـ pipeline الحالي (السطور 1010–1290) مع تغييرين: العنوان يعرض `dayLabel` واسم الملف `AZMA-Orders-<dayKey>.pdf`. زر التصدير القديم في رأس الصفحة يُزال.
- **`filterOrders()`** — بلا تغيير منطقي (تقرأ القيمتين وتعيد الرسم).
- **حذف:** `toggleGroupByRegion()`، `exportOrdersCSV()`، `renderOrdersTable()` و`renderOrdersGroupedByRegion()` (تُستبدل بالدالة الجديدة).
- **إضافة:** `resetOrdersDateFilter()` — تمسح فلتر التاريخ وتعيد الرسم.

## 4. `admin.html`

- شريط أدوات صفحة الطلبات:
  - يبقى: فلتر الحالة.
  - جديد: `<input type="date" id="orders-date-filter" onchange="filterOrders()">` + زر "عرض الكل".
  - يُحذف: checkbox "تجميع حسب المنطقة"، زر CSV، زر PDF العام.
- إضافة `<script src="js/order-days.js"></script>` قبل `js/admin.js`.

## 5. الحواف (Edge Cases)

- التوقيت: `createdAt` مخزّن UTC — التحويل للمفتاح يتم بالتوقيت المحلي حتى يطابق تقويم المستخدم.
- طلب بلا `createdAt`/تاريخ غير صالح → قسم "بدون تاريخ" في الآخر.
- يوم مختار بلا طلبات → رسالة فارغة واضحة.
- PDF ليوم فيه طلب واحد → يعمل (الـ pipeline يدعم أي عدد).

## 6. الاختبار والتحقق

- `tests/order-days.test.js` (vitest): `dayKey` بالتوقيت المحلي، ترتيب الأيام تنازلياً، ترتيب الطلبات داخل اليوم تنازلياً، قسم "بدون تاريخ"، استقرار الدوال النقية (بدون تغيير للمدخلات).
- `npm run lint` + `npm test`.
- فحص يدوي بالمتصفح: أقسام الأيام تظهر، فلتر التاريخ يعمل، فلتر الحالة يدمج معه، PDF كل يوم ينزل باسمه الصحيح، الموشن (stagger) يعمل على الأقسام الجديدة، مفيش أخطاء بالكونسول.
