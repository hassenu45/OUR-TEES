# AZMA — صفحة "طلباتي" للعميل (My Orders)

التاريخ: 2026-08-08

## الهدف

إعطاء العميل تجربة طلب على نمط المواقع التجارية الحديثة (مثل Temu):
- زر "إتمام الطلب" في المتجر يودي العميل على صفحة جديدة `my-orders.html` بدل الفورم الداخلي في السلة.
- الصفحة فيها تبويب "إتمام الطلب" (تعبئة البيانات + اختيار طريقة الدفع) وتبويب "طلباتي" (قائمة الطلبات + إلغاء).
- حفظ بيانات كل عميل (الاسم، الهاتف، تفاصيل العنوان) بشكل دائم في قاعدة البيانات، وعند عودته يكفي إدخال رقم الهاتف لتظهر بياناته وطلباته تلقائياً.
- إلغاء الطلبات من نفس الصفحة (للطلبات بحالة "جديد" فقط).
- طريقة الدفع: كاش عند الاستلام + دفع إلكتروني (محاكاة تجريبية — بدون بوابة دفع حقيقية).

## المكونات

### 1. صفحة جديدة `my-orders.html` + `js/my-orders.js`

صفحة عامة (ليست ضمن ADMIN_ONLY_PAGES في server.js) بنفس تصميم المتجر (design-tokens) وبأسلوب المواقع التجارية الحديثة:

- **تبويب "إتمام الطلب":**
  - ملخص السلة (المنتجات، المقاس، الكمية، السعر، المجموع) — تُقرأ من localStorage بنفس مفتاح سلة المتجر.
  - فورم البيانات: الاسم الكامل، رقم الهاتف، المدينة، الحي، الشارع، معلم قريب، ملاحظات.
  - طريقة الدفع: اختيار بين "كاش عند الاستلام" و"دفع إلكتروني" (محاكاة: شاشة معالجة تجريبية ثم نجاح الطلب).
  - زر "تأكيد الطلب": ينشئ طلباً لكل عنصر في السلة (نفس سلوك POST /api/orders الحالي) مع حقل paymentMethod، ويحدّث/ينشئ سجل العميل.
  - بعد النجاح: مسح السلة، ورسالة نجاح، والانتقال لتبويب "طلباتي".
- **تبويب "طلباتي":**
  - عند توفر رقم هاتف (من الطلب الأخير أو من إدخال المستخدم) يعرض كل الطلبات المرتبطة به: المنتج، المقاس، الكمية، السعر، طريقة الدفع، التاريخ، الحالة (جديد/مكتمل/ملغي).
  - زر "إلغاء الطلب" لكل طلب بحالة "جديد" — يطلب تأكيداً ثم يرسل طلب الإلغاء ويعيد التحميل.
  - عندما لا يوجد رقم هاتف محفوظ: شاشة صغيرة لإدخال رقم الهاتف لاسترجاع البيانات والطلبات.
- عند العودة لاحقاً: رقم الهاتف محفوظ في localStorage فيتم تعبئة الفورم وقائمة الطلبات تلقائياً.

### 2. قاعدة البيانات (Prisma)

- **نموذج جديد `Customer`:** id (cuid)، phone (فريد)، name، city، area، street، landmark، notes، totalOrders، lastOrderAt، createdAt، updatedAt.
- **حقل جديد `paymentMethod`** في نموذج `Order` (افتراضي "cod").
- ترحيل Prisma جديد للجداول (SQLite محلياً، ثم نفس المخطط للنشر).

### 3. السيرفر (server.js) — نقاط API جديدة

- `GET /api/customers/:phone` — عام + rateLimit: يعيد بيانات العميل وطلباته (بلا بيانات حساسة إضافية).
- `POST /api/orders/:id/cancel` — عام + rateLimit: يتحقق أن الطلب موجود، حالته "new"، وأن رقم الهاتف المرسل في body يطابق هاتف الطلب؛ عندها يغيّر الحالة إلى "cancelled" (لا حذف — يبقى في سجل الإدارة).
- `POST /api/orders` — يقبل `paymentMethod` اختيارياً ويخزنه. تفاصيل العنوان المفصلة (المدينة، الحي، الشارع، معلم) تُحفظ في سجل `Customer` (upsert برقم الهاتف مع زيادة totalOrders وتحديث lastOrderAt)، وفي الطلب نفسه يُدمج عنوان واحد في حقل address الحالي (كما هو الآن) — لا تغيير على شكل الطلب في لوحة التحكم.
- `GET /api/orders` (الإدارة) — يعيد paymentMethod مع الطلبات.
- قائمة العملاء في لوحة التحكم: **مؤجلة** — لا تُنفذ في هذه المرحلة.

### 4. المتجر (store.html)

- زر "إتمام الطلب" (#checkout-btn) يصبح رابطاً إلى `my-orders.html` (السلة محفوظة في localStorage فينتقل ملخصها معه).
- إزالة الفورم الداخلي القديم (checkout-form + دوال showCheckoutForm/hideCheckoutForm/submitCheckout) — السلوك يستبدل بالصفحة الجديدة.
- إضافة رابط "طلباتي" في هيدر المتجر بجانب زر السلة — يفتح my-orders.html مباشرة.

### 5. لوحة التحكم (admin.html / js/admin.js)

- عرض شارة طريقة الدفع (كاش 💵 / إلكتروني 💳) لكل طلب في قائمة الطلبات.
- الطلبات الملغاة من العميل تظهر بحالة "ملغي" كالمعتاد.

## تدفق البيانات

1. العميل يضيف للسلة → يضغط "إتمام الطلب" → `my-orders.html` (السلة تُقرأ من localStorage).
2. يعبي البيانات ويختار طريقة الدفع → "تأكيد الطلب" → لكل عنصر: `POST /api/orders` مع paymentMethod وتفاصيل العنوان → upsert Customer → مسح السلة.
3. الصفحة تجلب الطلبات عبر `GET /api/customers/:phone` وتعرض تبويب "طلباتي".
4. الإلغاء: `POST /api/orders/:id/cancel` (phone في body) → الحالة تصبح "cancelled" → تحديث القائمة.
5. العودة لاحقاً: الرقم محفوظ محلياً → تعبئة تلقائية + قائمة الطلبات.

## الأمان والقيود

- نقاط API العامة محمية بـ rateLimit (نمط موجود في server.js).
- إلغاء الطلب يتطلب مطابقة رقم الهاتف مع صاحب الطلب، وحالة "new" فقط.
- لا توجد أي بيانات دفع حقيقية — الدفع الإلكتروني محاكاة فقط (paymentMethod = "card" يُسجّل كاختيار تجريبي).
- `my-orders.html` و `js/my-orders.js` غير مدرجين في ADMIN_ONLY_PAGES.

## الاختبار

- اختبارات vitest للسيرفر:
  - إنشاء طلب مع paymentMethod يحفظ الحقل ويحدّث سجل العميل.
  - إلغاء الطلب: نجاح لحالة new بهاتف مطابق؛ رفض عند هاتف غير مطابق أو حالة غير جديدة.
  - جلب بيانات العميل بالهاتف يعيد بياناته وطلباته فقط.
- فحص يدوي للمسار الكامل (إضافة للسلة → صفحة الطلبات → تأكيد → إلغاء) عبر تشغيل السيرفر محلياً.

## خارج النطاق (مؤجل)

- بوابة دفع حقيقية (Stripe/Paymob).
- سلة مخزنة على السيرفر للعميل نفسه (تبقى محلية).
- صفحة عملاء منفصلة في لوحة التحكم (يمكن إضافتها لاحقاً).
